# POV Studio — Joxel's clips → POV Reels → Instagram (automatic)

Joxel: "I need the thing to upload my videos and make pov versions to post it automatically."

- **Upload page:** POV Studio artifact — https://claude.ai/artifact/NPYELDhaL44G4Fr6xTWDMu (private to Joxel). He adds clips from his camera roll, an optional line about what happens, "One Reel from all" / "One Reel per clip", "Music" / "Keep my voice". Files over 19 MiB go up in 19 MiB pieces (raw bytes, no re-encode). Each Reel is a doc in the page's database; the page then fires the routine (Claude Code Remote `fire_trigger`).
- **Routine:** "POV Studio — make + post POV Reels" (trigger id in the page's `settings/main.triggerId`; also fires every few hours as a fallback). Each firing runs this file in a fresh session with the Make connector.
- **Tools:** `tools/video/povcut.mjs` (prep / blur / render) + `tools/video/povblur.py` (YuNet face blur, manual boxes, contact sheets) + `tools/video/models/yunet.onnx`.

## Database (artifact db of the POV Studio page — use the ArtifactData tool with the URL above)
- `settings/main` = `{autoPost: true|false, account: "ds"|"sdx", triggerId}`.
- `batches/<id>` = `{status, createdAt, queuedAt, note, audio: "music"|"keep", auto, account, clips: [{name, ext, size, dur, w, h, thumb, chunks: [assetId, …]}], hook, cues, caption, outFile, outUrl, previewAsset, heldReason, error, postedAt, postId, permalink, log}`.
- Status flow: `uploading` (page) → `queued` → `processing` → `ready` (auto-post off: waits for his "✓ Post it") / `held` (needs his look) → `approved` (he tapped Post it) → `posted`; `failed` with `error`; `skipped` (he tapped Don't post). Only the page sets `approved` / `skipped`.

## Each run — do exactly this
1. `ArtifactData list` collection `batches`. Work on every doc with status `queued`, `approved`, or `processing` whose `processingAt` is older than 45 minutes (a run that died). Nothing to do → stop with one line ("POV Studio: nothing new").
2. Setup once: `cd /home/user/Claude && git pull origin main`; `[ -d node_modules ] || npm ci`; `npm i --no-save --prefix /tmp/ff ffmpeg-static`; `python3 -c "import cv2"` or `pip install opencv-python-headless numpy`.
3. **approved** batches (already rendered): go straight to step 10 with the stored `outUrl` + `caption`.
4. **queued** batches: `ArtifactData update` → `{status: "processing", processingAt: <now ISO>}`.
5. Download: `Artifact read` the page URL once, then for each clip `Artifact read` with `path: <assetId>` for every chunk (in order) — each lands as a local file; `cat` the chunks of one clip into `/tmp/pov/<batchId>/clip<N>.<ext>` (ext from the doc; mov / mp4 / webm all work).
6. Write `/tmp/pov/<batchId>/job.json` (format at the top of `povcut.mjs`): clips in upload order, `faces: true`, `audio` from the doc, `end: {handle: ""}` (no handle until @sdxinspect is connected), `out: "final.mp4"`. Long material: keep the Reel 12–40 s — trim each clip with `in`/`out` to its action (look at the sheet first). Run `node tools/video/povcut.mjs prep job.json`.
   Before writing the job, look at the RAW clip first (1-fps tile: `ffmpeg -i clip -vf fps=1,scale=200:-2,tile=10x4`) and zoom on the iPad screen at a few moments: the sign-in screen (badge keypad), the on-site lock with the stand finder, the Global Admin venue list and the form's top fields show the venue, stand names and license numbers — cut those parts out with `in`/`out`, don't try to blur them.
7. **Identity check — the most important step.** `appBar` is on by default: `povblur.py --app-bar` finds the app's navy header bar every frame (on the home venue it carries the employer's logo, the "Inspecting STAND" line and the browser tab title) and blurs it with padding. It can still miss the bar for a few frames — check every cut between parts and the moment the camera app opens (the bar sits on a black screen there) with `ffmpeg -ss <cut-0.2> -t 0.7 -i work/blurred.mp4 -vf fps=10,scale=216:384,tile=7x1`, and add a manual box when you see it. Read every `work/sheets/sheet_*.jpg` (Read tool). Anything that could identify the venue, the employer, a stand or a person must be blurred: faces the detector missed (side / back of head with a name, reflections), stand names and menu boards, logos on uniforms / caps / cups / signs (Sodexo, Hard Rock, Dolphins, any brand of a stand), license / permit / phone / badge numbers, other people's phone screens, the app showing a real stand name, the stadium's own signage. Add a box per item to `job.blur` (`t0`, `t1`, `x`, `y`, `w`, `h` as 0–1 of the 1080×1920 frame, generous margins), run `node tools/video/povcut.mjs blur job.json`, read the sheets again. If you cannot make it safe (the whole frame is the identifying thing, a face is too close to blur well, someone is in distress, a real violation at an identifiable stand) → `{status: "held", heldReason: "<plain words: what you saw and where>"}` and do NOT post; still render the preview so he can look.
8. Write the words from the sheets + his `note` (his note wins): `hook` = 2 short lines starting "POV:" (e.g. "POV: you check" / "100+ stands *alone*"; never name the stadium, Sodexo or a stand); 3–5 `cues` timed to what actually happens on screen (≤ 7 words each, one `key: true` on the moment that matters); `hookEnd` ≈ 3 s. No invented numbers — only readings visible on screen or in his note. `node tools/video/povcut.mjs render job.json`, then read `work/final_sheet.jpg`: text readable, nothing covers the action, no unblurred identifier. Fix and re-render once if needed.
9. Publish the file: copy to `docs/reels/<YYYY-MM-DD>-pov-<batchId>.mp4`, `git add` that one file, commit ("POV Reel <batchId>"), `git push -u origin main` (retry 4× with backoff on network errors). URL = `https://raw.githubusercontent.com/JoxelDS/Claude/main/docs/reels/<file>` — check it returns 200 with `curl -sI`. Upload a preview to the page: `Artifact publish` with `url` = the page, `file_path` = final.mp4, `asset: true` → `previewAsset` = the returned id. Assets are capped at 20 MiB: a longer Reel needs a 720p copy for the preview (`ffmpeg -i final.mp4 -vf scale=720:1280 -crf 24 -c:a aac -b:a 128k -movflags +faststart preview.mp4`); Instagram still gets the full file from `outUrl`. Chunks of his uploads are read one at a time with `Artifact read` + `path: <assetId>` (`paths` with several ids does not find assets). Caption (EN, then one short ES line, then "Free 30-day pilot — DM us PILOT", then ≤ 15 hashtags such as #foodsafety #restaurantinspection #kitchenmanagement #foodservice #concessions #stadiumfood #inspectionapp #restauranttech #haccp #pov #dayinthelife #foodinspector). Update the doc: `{hook, cues, caption, outFile, outUrl, previewAsset, status: held? "held" : (settings.autoPost && doc.auto !== false ? "posting" : "ready")}`.
10. Post (only when status is `posting` or `approved`, and only if the doc has no `postId`). Prefer `responsive: false` (returns the execution id at once; the responsive call can come back as a 502 from the gateway while the post goes through), then read `executions_get-detail` for `outputs.tool_output.id` after ~45 s: `settings.account` `ds` → Make scenario **6549655** "SDX Inspect - IG Reel Post" (posts to @dsmarketing.agency) via `mcp__Make__scenarios_run` `{scenarioId: 6549655, responsive: true, data: {video_url: outUrl, post_caption: caption}}`. `sdx` → the @sdxinspect scenario once it exists (docs/training/daily-reels.md); until then treat as `ds`. Instagram takes ~1–2 min. If the call times out or errors, check `mcp__Make__executions_list` for scenario 6549655 since the start of this run before retrying — never post twice. Read the post id from the result (or `executions_get-detail`, module 2 output `id`). Update the doc `{status: "posted", postedAt, postId}` (+ `permalink` if you have it).
11. Any failure: `{status: "failed", error: "<one plain sentence he can act on>"}` and move to the next batch.
12. End with one line per batch (posted / held + why / failed + why). Never delete his uploaded clips — the page has "Free up space" for that.

Rules: real footage only, nothing identifying, no Sodexo / Hard Rock / stand names in text or caption, never invent numbers, never post a `held` batch, never post the same batch twice. Joxel turned auto-post on ("post it automatically"); the page switch turns it off (then every Reel waits for his ✓ Post it).
