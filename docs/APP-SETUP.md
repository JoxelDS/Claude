# SDX Inspect as a real app (Capacitor) — setup & what's left

This branch finishes the Capacitor wrap that was already started on main:
the same web app now also builds as a native iOS/Android app named
**SDX Inspect**, app id **`com.sdxinspect.app`**, with push-notification
wiring in place. The website/PWA is untouched in behavior — every native
code path is guarded by a platform check and never loads on the web.

> ⚠️ **One pre-merge step — lockfile.** `package.json` in this branch adds
> `@capacitor/push-notifications` and `@capacitor/assets`, but
> `package-lock.json` could not be refreshed through the API channel used
> to assemble this branch (the file exceeds what that channel can carry).
> Before merging, from a normal checkout run:
>
> ```bash
> npm install   # refreshes package-lock.json for the two new deps
> git add package-lock.json && git commit -m "app: refresh lockfile"
> ```
>
> Until that commit lands, `npm ci` (used by the Pages deploy workflow)
> would fail on the mismatch — so do not merge without it. The updated
> lockfile was generated and verified during this branch's preparation
> (push-notifications 8.1.3, @capacitor/assets 3.0.5, lockfileVersion 3);
> it just couldn't ride along.

## What this branch changes

- `capacitor.config.json` — appId `com.sodexolive.sdxinspect` →
  `com.sdxinspect.app`; PushNotifications presentation options added.
  (`server.url` still points the shell at the live site, so app users get
  web updates instantly — see "Decision kept" below.)
- `package.json` — adds `@capacitor/push-notifications` (runtime) and
  `@capacitor/assets` (dev, regenerates icons/splashes), plus scripts
  `npm run app:assets` and `npm run app:sync`.
- `src/firebase.js` — `registerPushToken` (the call the app already makes
  at sign-in) now delegates to a new `registerNativePushToken` inside the
  native shell: OS permission prompt → plugin registration → token stored
  in the same `venues/<venue>/sharedMemory/pushTokens` doc as web tokens,
  tagged `platform` + `native: true`, so one sender list reaches both.
- `src/native/push.js` (new) + hook in `src/main.jsx` — native-only push
  listeners (foreground delivery re-dispatched as `sdx-push-received`
  window events; taps kept on `window.__sdxLastPushAction` +
  `sdx-push-action`). On the web the module is never imported.
- `android/` — package renamed `com.sodexolive.sdxinspect` →
  `com.sdxinspect.app` (namespace, applicationId, strings, MainActivity);
  plugin registration regenerated by `cap sync` (adds push-notifications);
  full adaptive-icon + splash set regenerated from the SDX mark.
- `ios/` (new) — complete generated Xcode project (SPM), bundle id
  `com.sdxinspect.app`, AppIcon + splash from the SDX mark,
  `App.entitlements` with `aps-environment`, `UIBackgroundModes:
  remote-notification` in Info.plist.
- `resources/` (new) — icon/splash masters (SVG sources + PNG renders)
  the asset set is generated from. Artwork is the SDX mark from
  `public/sdx-inspect-icon.svg` on the locked SDX navy `#2A295C`
  (splash on deep base `#16152E`). Note: the old 1024 web icon in
  `public/icons/` was still the Sodexo logo — the native set does **not**
  use it. If the rebrand updates the SDX mark, refresh with
  `npm run app:assets`.
- Placeholders (not real configs, safe to commit):
  `android/app/google-services.json.example`,
  `ios/App/App/GoogleService-Info.plist.example`.

> Binary note: this branch was assembled through an API channel that
> only carries text, so the generated icon/splash **PNG files** are not
> committed even though their Contents.json / resource XML references
> are. Run `npm run app:assets` once after checkout — it regenerates
> every PNG deterministically from `resources/`. The SVG masters and
> Android's vector launcher foreground are committed.

## What only Joxel can provide (in order)

1. **Firebase app registrations** (free, ~10 min, console of the
   existing Firebase project):
   - Android app with package name `com.sdxinspect.app` → download
     `google-services.json` → save as `android/app/google-services.json`.
   - iOS app with bundle ID `com.sdxinspect.app` → download
     `GoogleService-Info.plist` → save as
     `ios/App/App/GoogleService-Info.plist` and confirm Xcode includes
     it in the App target.
   - The placeholder `.example` files show the exact shapes.
2. **APNs key for iOS push** — Apple Developer portal → Keys → create an
   Apple Push Notifications service key (.p8) → upload it to Firebase
   console → Project settings → Cloud Messaging → Apple app
   configuration. Without it iOS devices can register but never receive.
3. **Developer accounts (deferred until revenue, per the budget rule)** —
   Apple Developer Program **$99/yr** (required to ship/test on real
   iPhones beyond a 7-day personal signature) and Google Play
   **$25 once**. Nothing in this branch needs them; local/simulator
   builds work without either.
4. **One decision — bundle ID.** This branch uses `com.sdxinspect.app`
   everywhere (Capacitor config, Android, iOS). The separate Xcode
   project created on the Mac used `sdxinspect.SDX-Inspection-System`.
   Pick ONE before any store submission or Firebase app registration is
   finalized — changing it afterwards means new store listings and new
   Firebase app entries. (The Firebase downloads in step 1 must use
   whichever ID wins.)
5. **Push sender** — token registration is wired; SENDING native pushes
   rides the same FCM project as web push. The existing Cloud Function
   (`notifyOnFix`) targets stored tokens; once native tokens appear in
   `pushTokens` with `platform` tags, the function can fan out to them
   (FCM accepts APNs-registered iOS tokens through the same API).

## Build & verify

```bash
npm install
npm run build            # web build → dist/ (also what Pages deploys)
npx cap sync             # copies dist into android/ + ios/, wires plugins
npm run app:assets       # regenerate icons/splashes from resources/

# Android: open android/ in Android Studio, or
cd android && ./gradlew assembleDebug   # needs a local Android SDK + JDK 21

# iOS (macOS only): open ios/App/App.xcodeproj in Xcode and run.
# No Mac handy? GitHub Actions macOS runners can compile it — add a
# workflow when the Apple account exists; this Linux environment cannot
# build iOS at all.
```

## Decision kept from the existing setup

`capacitor.config.json` keeps `server.url` pointing at the live site, so
the installed app loads the current web build (instant updates, no store
review per fix). Trade-off to decide before a public store listing:
Apple Guideline 4.2 can reject thin wrappers of a website. The bundled
copy of the same build is already synced into both native projects by
`cap sync` — removing `server.url` before a store submission switches
the apps to the bundled copy with no other changes.

visible in the system's data. Pick the set and the daily system audit
can start tracking them:

- ✅ Fixed — a corrective action is marked done (already built for web
  push: `notifyOnFix`; native tokens join the same list)

- Failed check logged, or a corrective action coming due / overdue
